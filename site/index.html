You’re working with files on your computer. Open your game’s folder in Cursor, Codex or Claude Code, then let your agent guide you through the checklist.

1. Sign up for Cloudflare

Cloudflare runs the online part of your game so friends can connect from their own computers. You’ll need your own Cloudflare account to put your game online. Create an account and finish the signup steps. You can try the demo locally first.

Create your Cloudflare account ↗

2. Open Cursor, Codex or Claude Code

Install and sign in to the coding tool you want to use. It needs access to your game’s files and permission to run the setup commands. Open your game’s folder in it, then paste the multiplayer prompt above. Tell it you’re a beginner and want help with setup.

3. Install Node.js

Node.js lets your computer run the tools that build and preview your game. Download the current LTS installer and follow its steps (this repo needs 22.12+). It also installs npm, which downloads other tools. Reopen your terminal after installing.

4. Install Git

Git downloads a copy of the lobbyboi example onto your computer and tracks changes to code. Download Git for your operating system and follow the installer. You don’t need a GitHub account to download this public example.

5. Install pnpm

pnpm downloads the code packages the example needs. After installing Node.js, open your terminal and run npm install -g pnpm@9.13.2. If you’re adding multiplayer to your own game, your agent should keep the package manager that game already uses.

6. Let the project install Wrangler

Wrangler is Cloudflare’s command-line tool. It runs a practice version of your multiplayer server on your computer and publishes it when you’re ready. The example installs it when you run pnpm install below. You don’t need to install it separately.

What’s a terminal?

It’s an app where you type commands. On macOS, open Terminal; on Windows, open PowerShell. Your code editor may also have a Terminal panel. Paste one line at a time, press Enter, and wait for it to finish before running the next. If you see an error, paste it into your coding agent and ask for help.

Try the example on your computer

Once Node.js and Git are installed, run these commands in order. They install pnpm, download the example, open its folder, install its dependencies and start it. Leave the terminal running, then open localhost:5180 for the site or /play/ for Coin Rush. “localhost” means this is running on your own computer; friends on other computers can’t use that address.

The dev script starts Vite and Wrangler and creates a local SESSION_SECRET in site/.dev.vars. Keep that file private. Open a private browser window for a second player; normal tabs share a session.

Just want the standalone game? Use pnpm dev instead and open the Vite URL printed in your terminal.

Next: put your game online so friends can join

This step is called deploying: uploading your game to Cloudflare so it has a public web address. Sign up for Cloudflare if you haven’t yet. Ask your agent to walk you through the steps below. You complete the account signup and browser login yourself. These commands are for the lobbyboi example; your agent should adapt them for your own game.

  1. In site/wrangler.jsonc, choose your own Worker name and remove the existing routes entry for lobbyboi.walt.online. Use your workers.dev URL to start.
  2. In your terminal, inside the lobbyboi folder you downloaded, run pnpm --filter site exec wrangler login and sign in to your Cloudflare account in the browser window that opens. This connects the publishing tool to your account.
  3. Run pnpm --filter site exec wrangler secret put SESSION_SECRET and enter a random secret of at least 16 characters. Your local secret isn’t uploaded automatically.
  4. Run pnpm run deploy to build and deploy the site and demo to your account. Cloudflare usage limits and charges apply to your account.

Your game has two parts

The part players see can stay hosted by your builder. The multiplayer server lives on Cloudflare. Your agent needs to connect the two using the server’s web address, allow connections from your game’s address, and test player sessions. Cloudflare login and a server secret are part of that setup. Keep the secret on the server.

A lot happens
between players.

Give your agent a foundation for the rooms, connections and match flow around your game.

Lobbies and quick-match

Readable room codes, a public room list and one-click quick-match. It reserves a seat before sending you in, so stale listings never strand a player.

A real match lifecycle

Ready-up, host controls, kick, chat, countdown, results and back again. Changing the rules un-readies everyone, so nobody agrees to a game they didn’t see.

Reconnects that keep your seat

One socket per player, so refreshing just works. Dropped players keep their slot, the client backs off and retries, and the host role moves on if the host leaves.

One shared source of truth

A fixed-step server tick with sequenced, validated, rate-limited inputs. Every snapshot carries an ack so clients can predict and reconcile.

Send only what changed

Per-connection, per-entity, per-field diffs. A moving player costs {"x":412}, not the whole world. Keyframes and resync handle lost baselines.

Bots that play fair

Bots fill empty seats and give them up when humans arrive. Their inputs go through the same path as players’, so your rules apply to them for free.

A little less jitter.
A lot more play.

Snapshots arrive late, in bursts, or not at all. The left side draws each one as it lands. The right side runs the same packets through lobbyboi’s Interpolator. The dashed ring is where the server really is.

Snapshot rate

One object per room, asleep when idle

Every room code maps to one Durable Object, so all players share one process and one source of truth. Timers are alarms, so a lobby of idle players hibernates and costs nothing. The tick loop only runs during a match.

  1. LobbyReady-up, bots, settingsalarm · hibernates
  2. CountdownCancelled if someone joins or un-readiesalarm
  3. Playingstep() at tickHz, snapshots at snapshotHzfixed-step loop
  4. ResultsWhatever step() returnedalarm

Small API.
Room for your ideas.

Your agent writes the game hooks and connects your UI. Peek at the shape of the code below, or explore the full README.

import { GameRoom, createLobby } from 'lobbyboi/server';

export class TagRoom extends GameRoom<State, Input> {
  static config = { maxPlayers: 8, tickHz: 30 };

  createGame(ctx) {
    return spawn(ctx.players); // bots included
  }
  step(state, ctx) {
    for (const [id, input] of ctx.inputs)
      move(state, id, input, ctx.dt);
    if (ctx.tick > 1800) return { winner: leader(state) };
  }
  view(state, playerId) {
    return { players: state.players };
  }
  botInput(state, botId) {
    return chaseNearest(state, botId);
  }
}

const lobby = createLobby({ rooms: 'ROOMS' });
import { LobbyClient, Interpolator } from 'lobbyboi/client';

const lobby = new LobbyClient();
await lobby.login('Walt');

const room = lobby.join(await lobby.quickMatch());
const others = new Interpolator({ delayMs: 100 });

room.on('room', (info) => renderLobby(info));
room.on('snapshot', ({ time, state }) =>
  others.push(time, state.players));

room.ready();
setInterval(() => room.sendInput(readKeys()), 33);

function frame() {
  draw(others.sample(room.serverTime()));
  requestAnimationFrame(frame);
}
